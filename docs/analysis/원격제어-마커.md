# 원격제어 마커 — 호스트·계정 상태 판독

`origin_channel`(폰에서 온 지시냐)은 **행동**을 판정한다. 이 문서가 다루는 마커는 **상태**다:
"이 머신에 원격제어가 설정된 적 있나". 둘은 다른 질문이고, 답할 수 있는 범위도 다르다.

구현: `clfx/sources/markers.py` · `clfx/sources/claude.py` · `clfx/sources/codex.py` ·
`clfx/codex_sqlite.py:enrollment_marker` · 노출 `GET /api/remote-control`.

## 왜 Event 가 아닌가

Event 는 "에이전트가 한 행동 하나"다(`docs/event-schema.md`). 설정 플래그를 Event 로 만들면
같은 사실이 타임라인에 한 줄 더 늘어 **과계수**가 난다 — 행동을 세는 통계가 상태 때문에 부푼다.
그래서 `source_warnings` 와 같은 계층(소스 메타)에만 싣는다.

## 마커 4종

| kind | 파일 | 값 | 휘발성 |
|---|---|---|---|
| `claude_remote_control_flags` | `~/.claude.json` | `hasUsedRemoteControl` · `remoteDialogSeen` · `remoteControlUpsellSeenCount` | 아니오 |
| `claude_bridge_sessions` | `~/.claude/sessions/<pid>.json` | `bridgeSessionId` | **예** |
| `codex_remote_control_setting` | `~/.codex/app-server-daemon/settings.json` | `remoteControlEnabled` | 아니오 |
| `codex_remote_control_enrollments` | `state_5.sqlite` `remote_control_enrollments` | 등록 행 | 아니오 |

`~/.claude.json` 은 `.claude/` **안이 아니라 옆**에 있다 — 소스 루트의 부모에서 찾는다.

## 판정 3값 (`signal`)

| 값 | 뜻 | 도구가 할 수 있는 말 |
|---|---|---|
| `configured` | 마커가 양성값을 들고 있다 | **"설정된 적 있다"까지만** |
| `none` | 파일을 읽었고 키도 있는데 값이 음성이다 | "이 마커는 음성이다" |
| `unknown` | 파일 없음 · 못 읽음 · 키 없음 | **아무 말도 못 한다** |

`marker()` 가 규칙을 코드로 강제한다.

- `status != "observed"` 면 `signal` 은 무조건 `unknown` 으로 내려온다.
- **휘발성 마커는 `none` 을 낼 수 없다** — `ValueError` 로 막는다.

없는 키는 `values` 가 아니라 `absent_keys` 로 보고한다. 구버전 CLI(키 자체가 없음)와
"꺼 둠"(`false`)은 다른 사실인데 한 칸에 넣으면 구분이 사라진다.

## 승격 금지 — 세 개의 함정

1. **`remote_control_enrollments` 0행 ≠ 미사용.** enroll 이 MFA 로 거부돼도 행은 안 남는다.
   그래서 빈 결과는 `none` 이 아니라 `unknown` 이다.
2. **`settings.json` 이 `true` ≠ 채널이 살아 있음.** 호스트 스위치일 뿐 연결 상태가 아니다.
3. **`sessions/<pid>.json` 이 없다 ≠ 원격제어를 안 썼음.** 정상종료하면 파일째로 지워진다.
   지금 살아 있거나 비정상 종료한 세션만 남는다.

요약(`summarize`)의 `claim` 은 `configured_before`(설정 흔적 있음) / `not_observed`(관측 없음)
둘뿐이다. **`not_used` 라는 값은 없다** — 이 계층은 미사용을 말할 수 없다.

## 뷰어

`GET /api/remote-control` 은 마커 요약에 이벤트 축 집계를 더해 돌려준다.

```jsonc
{ "markers": [...], "counts": {"configured":3,"none":0,"unknown":1},
  "claim": "configured_before", "caveats": [...],
  "events": { "origin_channel": {"remote":…, "local":…, "unknown":…, "not_observed":…},
              "origin_os": {"ios":…}, "bridge_session_events": …, "bridge_session_ids": [...] } }
```

`not_observed` 는 필드가 아예 없던 이벤트다. `unknown`(봤는데 못 가림)과 다르고 **둘 중
어느 것도 `local` 이 아니다.** 대시보드는 이 넷을 각각 다른 문구로 쓴다.

화면에서는 **이벤트 판정을 위, 마커를 아래**에 둔다. 순서가 뒤집히면 "설정돼 있음"이
"썼음"으로 먼저 읽힌다. 타임라인에는 `remote` 로 확정된 이벤트에만 📱 배지가 붙고
(`unknown` 에는 안 붙인다 — 미상을 강조하면 원격처럼 읽힌다), `📱 원격만` 칩으로 좁힐 수 있다.

## 실측 (2026-08-22, 이 PC · 146,289건 코퍼스)

| 마커 | 값 | signal |
|---|---|---|
| `claude_remote_control_flags` | `hasUsedRemoteControl=true` · `remoteDialogSeen=true` · `remoteControlUpsellSeenCount=3` | configured |
| `claude_bridge_sessions` | 세션 파일 393 · 브리지 4(고유 id 1종) · 명시적 null 5 · 키 없음 384 | configured |
| `codex_remote_control_setting` | `remoteControlEnabled=true` | configured |
| `codex_remote_control_enrollments` | 1행 (`environment_id` 있음) | configured |

브리지 4건은 **같은 세션의 pid 파일 4개**다(정상종료 못 한 잔존). 세션 수가 아니다.

이벤트 축: `remote 1,258` · `local 5,116` · `unknown 3,313` · **필드 부재 136,602**.
`origin_os` 는 `ios 1,006` 뿐이다(Codex 원격 로그에만 실리는 축).
`bridge_session_id` 는 13,266건 · 고유 id 3종.

> 마커 4종이 전부 `configured` 인데 **원격 이벤트는 전체의 0.9%**다. 이게 두 계층을 나눠
> 놓아야 하는 이유다 — 마커만 보면 "이 머신은 원격제어를 쓴다"로 읽히지만, 실제 행동은
> 1%도 안 된다.

### 같은 브리지 세션인데 접두사가 다르다 (2026-08-22 발견)

| 아티팩트 | 값 |
|---|---|
| `sessions/<pid>.json` `bridgeSessionId` | `session_01GNKcPCJv1WyipeSuHPUeGY` |
| transcript `bridge-session` 레코드 | `cse_01GNKcPCJv1WyipeSuHPUeGY` |

**뒤쪽 ULID 가 같은 하나의 세션이다.** 문자열이 달라 서로 무관해 보이므로 그냥 세면
브리지 세션 수가 부풀려진다. 13단계에서 확인한 "계층마다 접두사가 다르다"가 이 계층에도
그대로 있다. 뷰어는 이 줄을 화면에 못 박아 둔다.
