# 모바일 원격제어 아티팩트 분석 — 별도 세션 인계 문서

신청서 §3.3 "본 과제의 핵심". 이 저장소의 로컬 파싱 작업(1~9단계)과 분리된 작업줄기라 **별도 세션에서 수행**한다.
작성 2026-08-21 (panel0). 패널 마감 2026-08-23 23:00.

## 1. 시나리오 매트릭스 — 4개 전부

| # | 단말 | 에이전트 | 폰 측 취득 방법(1순위) | 비고 |
|---|---|---|---|---|
| S1 | iOS | Claude Code | iTunes/Finder 백업(암호화 해제) → 앱 컨테이너 | 탈옥 불필요 |
| S2 | iOS | Codex | 동일 | |
| S3 | Android | Claude Code | `adb backup` / `adb shell run-as` / 루팅 시 `/data/data` 직접 | |

로컬 PC 측은 4개 시나리오 공통(`~/.claude`, `~/.codex`).
**교차 대조가 목적** — "폰에서 누가 언제 무엇을 지시했나" ↔ "로컬에서 무엇이 실행됐나".

## 2. 이미 확보된 단서 (분석 착수점)

| 에이전트 | 아티팩트 | 관측 |
|---|---|---|
| Claude Code | `~/.claude.json` | `hasUsedRemoteControl = true` · `remoteDialogSeen = true` · `remoteControlUpsellSeenCount = 3` · `oauthAccount`(accountUuid·organizationUuid 등) |
| Codex CLI | `state_5.sqlite` → `remote_control_enrollments` | 스키마 실재, 현재 0 rows. 컬럼: `websocket_url` `account_id` `app_server_client_name` `server_id` `environment_id` `server_name` `updated_at` `remote_control_enabled` |

→ **원격제어 활성화 시 이 두 곳이 먼저 변한다는 가설**을 세우고 실험으로 검증할 것.
Codex `config.toml` 에는 원격 관련 키가 현재 없음(0건) — 활성화 후 생기는지 확인.

## 3. 통제 실험 절차 (시나리오별 반복)

원본 무변경. 취득 도구는 `scripts/remote-snapshot.py` (read-only, 파일별 size·mtime·SHA-256).

```bash
# 1) 사전 스냅샷
python3 scripts/remote-snapshot.py snap S1-before artifacts/remote

# 2) 원격제어 세션 1회 실행
#    - 로컬에서 원격제어 활성화
#    - 폰 앱에서 명령 1건 지시 (권장: 특정 표식 파일 읽기 — 예: /tmp/AGENTRACE-MARKER.txt)
#    - 지시 시각·문구를 사람이 별도 기록 (폰 화면 캡처 = 대조 기준점)

# 3) 사후 스냅샷 + 차분
python3 scripts/remote-snapshot.py snap S1-after artifacts/remote
python3 scripts/remote-snapshot.py diff artifacts/remote/snap-S1-before.json artifacts/remote/snap-S1-after.json
```

표식 파일을 쓰는 이유: 로컬 이벤트 수만 개 중에서 **이 원격 지시로 발생한 행위를 유일하게 특정**하기 위함.

차분 후 확인 항목:
1. `~/.claude.json` 원격 관련 키 변화
2. `state_5.sqlite` `remote_control_enrollments` 신규 row (websocket 엔드포인트·server_name·account 식별자)
3. 세션 JSONL에 **원격 여부를 구분하는 필드**가 있는가 (없으면 "로컬 기록만으로는 원격/로컬 구분 불가"가 그 자체로 발견)
4. 신규 디렉터리·토큰·캐시 (Codex `.tmp`, Claude `.claude/` 하위)
5. 우리 도구로 파싱했을 때 그 행위가 Event로 잡히는지, actor가 무엇으로 판정되는지

## 4. 폰 측 취득

- **iOS**: 암호화 백업 생성 → `Manifest.db` 에서 앱 도메인 조회 → Claude/Codex 앱 컨테이너의 `Library/Preferences`·`Documents`·WebKit 저장소. 세션 토큰·원격 지시 이력·계정 식별자 위치 규명.
- **Android**: `adb backup -apk -noshared <pkg>` 또는 루팅 시 `/data/data/<pkg>`. SharedPreferences·Room/SQLite·OkHttp 캐시.
- **주의**: 토큰·인증값은 **존재·위치·형식만** 기록. 값 자체를 문서·패널에 싣지 않는다.

## 6. 실패 시 축소안

폰 취득이 시간 안에 안 되면 **로컬 측 규명만으로 정직하게 표기**한다:
"원격제어 연동 구조 규명 + 로컬 측 잔존 아티팩트 실측 완료 / 단말 측 추출은 후속 과제".
§2의 두 아티팩트는 이미 확보돼 있으므로 패널 ②③이 비지는 않는다.
